2. DS single-player, DST host and DST client must be distinguished

The installed product and all inspected scripts are Don't Starve Together,
not the separate Don't Starve / Reign of Giants single-player executable.
A video tagged 饥荒联机版 is DST; one person in a world is still not evidence
that it is the DS single-player product or that it is a zero-latency master sim.

Local authoritative path:
- components/inventory.lua:2270-2302 UseItemFromInvTile checks busy and pushes
  the selected action through locomotor.
- components/inventory_replica.lua:482-489 chooses authoritative Inventory
  or inventory_classified, depending on whether the component is present.

Remote / predicted path:
- prefabs/inventory_classified.lua:901-921 checks local busy state, selects an
  inventory action, then calls RemoteUseItemFromInvTile.
- components/playercontroller.lua:5565-5582 sends RPC.UseItemFromInvTile.
- components/combat_replica.lua:136-157 keeps client-side attack timestamps;
  authoritative Combat is still used when present.

Therefore host/master-sim timing and client-visible animation timing must not
be conflated. Local caves or dedicated-server configurations can still have a
client/server boundary. This research did not measure a specific network RTT
and does not justify hard-coding a universal extra number of delay frames.

3. Equipment switching and attack cooldown

Source facts:
- tuning.lua:43 WILSON_ATTACK_PERIOD = 0.4 seconds.
- stategraphs/SGwilson.lua:10898-10928 ordinary held weapons use atk_pre/atk
  and a state timeout of at least 13 * FRAMES.
- SGwilson.lua:11066-11075 performs the normal weapon hit at 8 * FRAMES and
  removes abouttoattack.
- SGwilson.lua:11100-11101 equipment changes leave the attack state for idle.
- SGwilson.lua:11109-11116 calls CancelAttack only if abouttoattack remains.
- components/combat.lua:128-145 implements a single character attack timestamp
  and minimum period. StartAttack at 763-767 restarts this cooldown.
- components/combat.lua:770 aliases CancelAttack to ResetCooldown.
- components/equippable.lua, inventoryitem.lua and the ordinary Equip path do
  not independently reset combat cooldown every time a weapon is swapped.

Implementation implication:
Switching before the hit cancels that unlanded attack; no damage should survive.
Switching after the hit can leave the attack animation / chain state, but the
already-started combat cooldown remains. Two weapons do not provide two separate
attack cooldown pools. A mod that explicitly calls ResetCooldown on each swap
is not evidence for vanilla behavior.
The exact one-tick ordering of input and state transitions should be validated
by the combat implementation; neither the video title nor an 8-frame hit point
justifies allowing one landed attack every 8 frames.

4. The native inventory is 15 storage slots plus distinct equipment slots

- widgets/inventorybar.lua:244-284 creates num_slots storage InvSlot widgets
  and separate EquipSlot widgets. Gaps are grouped every five storage slots.
- Equipped weapons move out of storage into EQUIPSLOTS.HANDS. They are not
  permanent duplicated weapon icons in the original storage slot.
- Inventory:Equip at components/inventory.lua:1286-1296 records the incoming
  item's own prevslot / prevcontainer. It removes the incoming item, unequips
  the previous item and gives the previous item back at 1349-1365.
- Inventory:GiveItem at 1062-1095 prefers the returning item's own previous
  empty slot, then falls back to the next available slot.
- The controller-specific same-slot swap at 1298-1302 is not the default
  keyboard/mouse path.

Example: put spear in slot 1 and cane in slot 2. Equip spear -> slot 1 becomes
empty, spear is in hands. Equip cane with key 2 -> spear returns to its original
slot 1 if free, slot 2 becomes empty, cane is in hands. Key 1 then reverses it.
Pressing the key for an empty storage slot does nothing; it does not toggle the
currently equipped item just because that item used to occupy the slot.

6. Mouse interaction: storage slots

Authoritative UI routing: widgets/invslot.lua:10-60, 100-198, 396-401.
ItemTile itself only refreshes tooltips in itemtile.lua:442-444; the slot owns
the click behavior.

Left click, no modifiers:
- Empty cursor + item slot: take the item/stack into the cursor active item.
- Held cursor item + empty slot: place it in that slot.
- Held cursor item + occupied different item: swap; old slot item becomes
  the cursor item, and the cursor item occupies the slot.
- Matching stackable items: merge the stack, subject to capacity.
This is click-to-pick-up and click-to-place, not merely drag-sort and not
left-click-to-equip. Supporting optional pointer drag in addition is an extra
convenience; it must not replace these native left-click semantics.

Right click, no modifiers:
- InvSlot:UseItem -> inventory:UseItemFromInvTile.
- With no cursor item this selects the default inventory action. For ordinary
  unequipped spear/cane it is EQUIP; for already equipped gear it is UNEQUIP.
- With a cursor item, it can use that item on the clicked inventory item.
- componentactions.lua:2692-2705 supplies EQUIP / UNEQUIP for equippables.
- actions.lua:858-884 executes the actual inventory equip / return action.

Modifiers relevant to a broader inventory implementation:
- Ctrl (force stack) + left click splits a stack; with an active stack places
  one into an eligible slot. Not relevant to unstackable spears/cane.
- Shift (force trade) + left click transfers to an eligible open container.
- Alt (force inspect) + left click examines.
- Shift + right click uses DropItem in InvSlot:OnControl, except restricted
  locked-slot branches. A trainer need not fabricate container/drop systems.

7. Mouse interaction: the separate hand equipment slot

widgets/equipslot.lua:31-68:
- Left click with empty cursor takes the equipped item into the cursor.
- Left click while holding a compatible item equips it; if hands already
  contain equipment, SwapEquipWithActiveItem swaps it with the cursor item.
- Right click calls UseItemFromInvTile; ordinary equipped weapon/cane uses
  UNEQUIP and returns it to inventory. This is different from right-clicking
  empty world space to start the spear's targeting mode.

8. Native recharge display versus durability number

widgets/itemtile.lua:129-185 builds recharge_meter UIAnim frame and fill.
Normal cooldown uses dark-blue frame and blue recharge overlay. The special
rechargeable_bonus tag uses green; it is not the usual lightning spear state.
SetChargePercent at 619-658 seeks the recharge animation by charge percent,
shows the frame while incomplete, and on completion plays frame_pst / briefly
white coloring before hiding the frame.
SetChargeTime at 661-667 and OnUpdate at 786 extrapolate percent over time.

There is no numeric remaining-seconds text created by this recharge code.
The percentage text at itemtile.lua:587-602 is durability/uses/fuel, and must
not be relabeled as a skill-cooldown percentage or seconds countdown.
If a numeric countdown is added for practice it is an explicit trainer feature,
not a claim of untouched native UI. A faithful baseline uses recharge artwork.

9. Lightning spear right-click -> aim arrow -> left-click confirm

components/playercontroller.lua:
- OnRightClick at 4999-5001 cancels existing AOE targeting.
- OnRightClick at 5010-5025, when no other contextual RMB action takes priority,
  returns the cursor item and calls TryAOETargeting.
- TryAOETargeting at 1609-1621 checks the held item's aoetargeting, skill / charge
  enabled state and riding restrictions, then starts targeting.
- OnLeftClick at 4728-4745 reads CASTAOE while aiming, pings the reticule and
  cancels targeting when the action is committed. An invalid action does not
  cast; busy feedback blips the reticule and uses click_negative.
- Clicking HUD is handled separately at 4702-4704 and 5002; a right click on an
  inventory icon should not accidentally launch the world-space skill.

components/aoetargeting.lua:98-119 creates/removes the reticule component.
prefabs/spear_wathgrithr.lua:430-438 selects reticuleline/reticulelineping,
mouse targeting, a golden valid color {1,.75,0,1}, and dark-red invalid color.
Its mouse target at 211-226 normalizes the vector to a fixed 6.5-world-unit
distance. Mouse movement changes direction, not dash distance.
The skill is enabled only when charged and arsenal_spear_4 is active (62-64).
Equipping an enabled spear can discharge it back to its 3-second cooldown when
the remaining recharge time is shorter (103-108). Switching to it is therefore
not a way to obtain an immediately ready dash on every equip.
